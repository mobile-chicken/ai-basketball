# 篮球集锦：本地可行性验证

## 当前运行版本（2026-09-30）

项目入口是 `run_highlights.bat`。把视频放入 `input` 后双击运行；程序会为每个视频独立自动标定篮筐、检测篮球、按轨迹判断进球，并把片段写入 `output`。模型权重位于 `models/yolo11s.pt`，处理依赖见 `requirements-lock.txt`。

GitHub 仓库只保存代码、配置、测试和模型权重。原始视频、训练样本视频、缓存、虚拟环境和运行输出保留在本机并由 `.gitignore` 排除，避免把多 GB 视频提交到仓库。

### 0018 漏检调整

轨迹续接上限从 0.36 秒放宽到 0.60 秒，穿网观察窗口从 0.85 秒放宽到 1.20 秒；允许球在筐口附近停留后落下。过大的球/篮网合并框不再参与关联，以免抢占正常球轨迹。保留筐口、下方重现、侧向逃逸和穿网证据检查。

每次结果中的 `review_candidates` 保存未通过进球规则的近筐过程，供人工查漏；它们不是进球结果或已标注负样本。人工核对后可移动至 `sample/in` 或 `sample/out`。完全未被球检测器发现的过程仍可能缺失。没有自动训练，也没有把已知时间点用于推理。

0018 全段同一检测缓存复算：原规则 4 个候选，新规则 7 个，找回用户指出的约 24.48 秒进球，并另导出 21 个待标注过程。0019 缓存回归仍排除用户标出的 4 次误检；新放宽规则带来的其它新增候选尚需人工复核。

双击 `run_highlights.bat`，将视频放入 `input`；默认自动标定，前 4 秒、后 2 秒，确认后陆续输出。主流程为 `run_pipeline.py`，篮筐定位为 `calibration.py`，轨迹关联和进球判定为 `shot_logic.py`。下方旧原型记录仅供历史参考。

当前仍使用本地 YOLO11s 通用球检测权重，没有训练新的进球分类模型。进球由 Python 时序规则判断：同一球轨迹从筐口上方下降，穿过内侧，并在下方连续重现；拒绝尺寸跳变、侧向逃逸和向上反弹。对投影重叠的三不沾，额外要求减速或近筐短暂遮挡后续接证据。该规则无法从单目画面完全证明球的深度位置。

自动标定使用多帧稳定红色结构，不再放大候选宽度；结果保存为 `calibration.jpg`。这是针对固定机位、红色篮圈的颜色/几何方法，不是通用篮筐神经网络。仍有中心位置先验；多篮筐、移动机位、无红色篮圈以及长遮挡场景尚未验证。每次会重新标定，不按文件名加载坐标。

每次运行保留 `detections.jsonl`（检测缓存）、带证据轨迹的 `events.json`、标定图；批处理同时保存 `run.log`。事件报告在运行中更新。已有结果时新一轮写入 `run_时间` 子目录，避免旧误检混入新结果。检测权重、格式与片段时长不因调参改变。

运行 `python -m unittest test_shot_logic -v` 检查合成边界案例；`validate_cached.py` 用生产规则复算检测缓存。合成测试不能代表实际召回率。输出仍为待人工核对的候选，尤其快速空心球和遮挡进球可能漏检。

# 批量使用

1. 把待处理的视频放入 `input` 文件夹。
2. 双击 `run_highlights.bat`。
3. 结果按视频分别写入 `output\视频文件名\`，每个进球片段为 MP4，并生成 `events.json`。

批处理会显示所有视频的总时长，并按已处理视频时长显示整体进度。默认截取进球前 4 秒、后 2 秒。导出使用原视频流复制，保留源视频的编码、分辨率、帧率、像素格式和音频；由于不重新编码，片段起点可能对齐到附近关键帧。

BAT 默认使用 `--rim auto`，每个视频开始时自动重新标定。
